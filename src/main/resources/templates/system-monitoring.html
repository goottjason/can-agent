모니터링 방식

데이터 수집부터 매매 실행까지 전체 흐름

전체 흐름도

1
데이터 수집 (04:00 ET)

개장 전(pre-market 04:00 ET) DataSyncScheduler가 가격 데이터를 토스 API에서 조회하여 stock_prices 테이블에 저장합니다. 분기별로 SEC EDGAR에서 재무제표를 수집합니다.

2
전체 점수 산출 (07:00 ET)

AutoTradingWorker가 전체 활성 종목을 전수 분석합니다. 각 종목의 CANSLIM 6요소 점수와 컵앤핸들 점수를 계산하여 analysis_scores 테이블에 UPSERT합니다. 이 과정에서는 매수/매도를 실행하지 않습니다.

3
대상 종목 필터링

전일 기준 거래량 상위 200종목 + 변동률 상위 200종목을 선별합니다. 중복 제거 후 약 300~400종목이 매수 후보가 됩니다. 전체 활성 종목을 전수 스캔하는 방식 대비 장중 스캔 시간을 크게 단축합니다.

4
장중 매도 체크 (09:30~16:00 ET, 5분마다)

보유 종목(최대 20개)의 현재가를 조회하여 세 가지 조건을 검사합니다. 조건 충족 시 즉시 매도 주문을 실행합니다.

5
장중 매수 스캔 (09:30~16:00 ET, 5분마다)

필터링된 ~400종목에 대해 현재가 조회 → CANSLIM/컵앤핸들 분석 → 점수 UPSERT → 매수 조건 충족 시 주문 실행. 500ms 간격으로 API 호출하여 속도를 제한합니다.

6
알림 발송

매수 체결, 손절, 익절, 점수 하락 매도 시 Telegram으로 한국어 알림을 발송합니다.

스케줄러 구조

스케줄러크론작업
DataSyncScheduler 매일 04:00 ET 가격 데이터 동기화, 분기별 재무제표 수집
AutoTradingWorker 매일 07:00 ET 전체 종목 분석 → 점수 저장 (매수/매도 없음)
IntradayMonitorWorker 09:30~16:00 ET, 5분마다 매도 체크 + 매수 스캔 + 점수 UPSERT
PortfolioScheduler 09:30~16:00 ET, 5분마다 보유 종목 현재가 갱신
스레드 풀: SchedulingConfig에서 ThreadPoolTaskScheduler(3 threads)를 사용합니다. AutoTradingWorker가 장시간 실행되어도 IntradayMonitorWorker를 차단하지 않습니다.

보유 종목 필터링

장중 스캔 대상은 전체 종목이 아닌, 전일 데이터 기준으로 선별된 종목입니다.

기준수량소스
거래량 상위200종목stock_prices.volume
변동률 상위200종목stock_prices.change_rate (절대값)
중복 제거 후약 300~400종목Set 합집합

API 속도 제한

토스 API의 요청 제한을 피하기 위해:

  • 현재가 조회: 종목당 500ms 간격
  • 매수 주문: 건당 1초 간격
  • 매수 실패 시 최대 3회 재시도
  • 장중 스캔 ~400종목 × 500ms ≈ 약 3분 소요
