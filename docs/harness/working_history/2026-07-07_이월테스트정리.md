## 원인 확정 (증거 기반)

### 1. CanSlimAnalysisServiceTest > "부분 점수 → 일반 매수" (line 130)
- 실패: 요소합 72점에 `isStrongBuy()`가 true인데 테스트는 false 기대.
- 코드: `CanSlimResult.isStrongBuy()` = 총점 ≥ **60**(DTO:67). 72 ≥ 60 → true. 테스트가 stale.
- **핵심 판정**: `isStrongBuy()`는 **프로덕션 어디서도 호출되지 않음**(grep 전수 확인 — DTO 정의만 존재). 매수 게이트는 `isBuySignal(≥40)` + `min-score(≥120)`만 사용. 즉 strong-buy 임계값은 실매매 무영향 정보성 코드.
- **조치**: 임계값(60)은 손대지 않음(변경 사유 없음 + 판단 기준 보존). 테스트의 의도("부분 점수 = 일반 매수, strong 아님")를 살려 mock 합계를 60 미만으로 조정: 72 → **54**(14+14+10+8+4+4). isBuySignal true / isStrongBuy false가 이제 코드와 일치.

### 2. KrxDataSyncServiceTest > "전체 활성 종목 동기화" (line 146)

- 코드: `syncAllActiveStocks`가 종목별 `getDailyPrices(code,start,end)` → **날짜별 전종목 배치 `getAllDailyPrices(dateStr)`**(KrxDataSyncService:106)로 리팩토링됨. 테스트가 옛 시그니처를 검증하던 mock 드리프트.
- **조치**: 테스트를 배치 방식으로 갱신 — 불필요해진 `findByCode` stub 제거, `getAllDailyPrices(anyString())` mock, 단일 거래일 → `times(1)` 검증 + `getDailyPrices` `never()` 추가.
