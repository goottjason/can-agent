## #2 — DB 마이그레이션 SQL 준비
prod DB(`canagent`) 현재 스키마 실측 후 ddl-auto=update가 못 바꾸는 **기존 컬럼 ALTER**만 작성:
- `financial_statements.eps` numeric(19,2)→(19,4) (미국 EPS 소수정밀)
- `financial_statements.debt_ratio` numeric(5,2)→(12,2) (고부채·자본잠식 오버플로 방지)
- `financial_statements.fiscal_quarter` NOT NULL 해제 (연간행 수용)
- 신규 컬럼(period_type/currency, stocks.cik/ticker/exchange/currency/sic_code)은 배포 시 Hibernate `update`가 자동 추가 → SQL 미포함.
- 파일: **`scripts/db/us-pivot-migration.sql`** (적용은 배포 #9에서 승인 후, 백업 권장).
- **국내 데이터 현황**: stocks에 KOSPI 835·KOSDAQ 1821·KONEX 107 = **2763건 active**. 미국 컷오버 시 `UPDATE stocks SET active=false WHERE market IN ('KOSPI','KOSDAQ','KONEX')` (삭제 아닌 비활성 — FK 히스토리 보존). SQL 주석에 명시, 실행은 #9.

## #3 — 미국 유니버스 적재
- **유니버스 규모 결정(사용자)**: 소규모 큐레이션 ~100(30은 부족 판단). 유동성 대형주(S&P 100급).
- **데이터**: `src/main/resources/company_tickers.json` — SEC 공식 `company_tickers_exchange.json`(9304종목)에서 큐레이션 티커의 실 CIK·거래소 추출, 로더 포맷(`cik_str/ticker/title/exchange`)으로 **100종목**(NYSE 64·NASDAQ 36). 나중에 행 추가로 확장.
- **트리거 배선**: `SecTickerUniverseLoader.loadFromClasspath()` 호출부가 없었음 → `StockController`에 **`POST /stocks/load-universe`** 추가(빈 주입, upsert 건수+거래소 카운트 JSON 반환). P9에서 제거된 KRX `/sync`의 미국판.
- **GOOG/GOOGL 이중상장 가드**: 로더 `findByCik` 폴백이 같은 CIK(1652044) 공유하는 GOOGL/GOOG를 병합 → 99종목·티커 소실이던 것을, "cik 폴백 행이 이미 다른 ticker 소유면 재사용 안 함(ticker null일 때만 재매칭)"으로 가드 → **distinct 100 유지**. 실계좌상 GOOG·GOOGL 별개 거래대상이라 distinct가 옳음(사용자 승인).
- **대시보드**: `stock-list.html`에 "미국 유니버스 적재" 버튼(JS fetch — 엔드포인트가 JSON 반환이라 PRG 아님), 성공/실패 alert.
- **테스트**: 통합(실 company_tickers.json 로드→100·NYSE64·NASDAQ36·getStockCountByMarket 합 100·필드 채움), 회귀(sameCikDifferentTicker_notMerged).
