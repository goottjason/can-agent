- **날짜**: 2026-07-16
- **리스크**: 중대(실계좌 실구매, 외부 사이트). 사용자 명시 승인하 각 구매 실행.
- **목표**: 랜덤 숫자로 연금·로또 1개씩 실구매 + 미구현 부분 구현.
- **실행 위치**: 서버 168.107.31.154 호스트 venv `~/lottery-venv`(격리). 크리덴셜 `sidecar/lottery/.env`(권한 600, 사용자가 직접 설정, git 미추적).

## 발단·현황
복권 부가기능이 머지돼 있었으나 사이드카(`sidecar/lottery/buy.py`)가 미검증:
- **로또**: dhapi 사용부가 옛 API(`dhapi.router.dhlottery_client`) 가정 → 설치본 **dhapi 4.2.4**와 불일치.
- **연금(WIN720)**: `_win720_interaction`이 `NotImplementedError` 스텁("게임 제한 로또"의 원인).

## 구현·수정 (buy.py, requirements.txt)
### 로또 — dhapi 4.2.4 대응
dhapi 4.x는 `LotteryClient(User(id,pw), endpoint)` 생성자에서 **RSA HTTP 자동 로그인**(OCR 불필요), `show_balance`/`buy_lotto645`는 값 반환 대신 **endpoint 프린터로 출력**. → 값을 캡처하는 `_CaptureEndpoint` 주입. `Lotto645Ticket.create_auto_tickets(1)`로 자동 1게임. 회차는 `client._get_round()`.

### 연금720+ — Playwright + 세션쿠키 주입 (신규 구현)
공개 HTTP 구매 구현이 없어(roeniss #5 미지원, techinpark은 Playwright+OCR), **dhapi의 RSA HTTP 로그인 세션 쿠키를 Playwright에 주입**해 로그인·보안키패드 OCR을 우회. 라이브 확정한 흐름:
- 구매 UI는 `el.dhlottery.co.kr/game/TotalGame.jsp?LottoId=LP72`의 **iframe `ifrm_tab`**(`/game/pension720/game.jsp`) 안.
- **단일 조**(랜덤 1~5) 선택 필수 — "모든 조"는 5장(5,000원)이 됨. `span.lotto720_box.jogroup.num{N}` 클릭.
- `doAuto()`(자동번호) → `doVerify()`(선택완료) → `doOrder()` → `doOrderRequest()`(실구매).
- **버튼 클릭 대신 JS 함수 직접 호출**(`doOrder`가 네이티브 `confirm()`을 띄워 클릭과 엉킴). `page.on("dialog", accept)`로 확인창 자동수락.
- BUY_NO 예 "4481478" → `4:481478`, 회차 `#DROUND`.
