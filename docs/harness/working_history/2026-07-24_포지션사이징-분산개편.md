# 2026-07-24 포지션 사이징 분산 개편 (reflow 제거 · 총자산 기준 균등)

## 과제
실매매 첫날 시드 소액으로 **2종목을 50/50으로 전액 소진** → 이후 예수금 0으로 매수 중단. 다양한 종목으로 분산된 포트폴리오를 구성하도록 사이징 로직 개편.

## 원인 (조사 확정)
`IntradayMonitorWorker.planPurchases()`의 **잔여현금 이월 재배분(reflow)** 단계가 `position-rate`(당시 10%) 상한을 무시하고 남은 현금을 신호 종목 수로 균등 분배했다. 신호가 2개뿐이면 각 10% 배분 후 남은 80%를 40%씩 추가 → 강제 50/50 + 현금 100% 소진. 이후 `availableCash=0` → `INSUFFICIENT_CASH`로 신규 매수 전면 차단.

## 사용자 결정
1. **비중 기준**: 총자산(현금+보유평가액, `balance.totalEval()`) 기준 균등 → 종목당 상한 = `totalEquity × positionRate/100`
2. **목표 분산**: 20종목 × 5% (`max-positions=20`, `position-rate=5`)
3. **사이클 상한**: 종목당 상한만 (사이클 총투입 별도 제한 없음)

## 변경 요약

### Backend (`IntradayMonitorWorker.java`, `TradingStrategyService.java`)
- `planPurchases()` 시그니처에 `totalEquity` 추가. 종목당 상한 = `totalEquity × positionRate/100`, 실제 배분 = `min(cap, 남은 가용현금)`.
- **reflow 단계 완전 제거** — 잔여 현금은 미배분(dry powder)로 보유. 이번 수정의 핵심.
- 호출부 `executeBuyOrders`: `balance.totalEval()`(총자산)과 `balance.availableCash()`(가용현금)를 분리 전달.
- `TradingStrategyService.evaluateBuy()`도 총자산 기준 상한으로 정합(비프로덕션 경로임을 주석 명시).
- 스테일 주석 정합(L119 `≤10개→≤20개`).

### Config (`application.yml`, `application-prod.yml`, @Value 기본값)
- `trading.max-positions` 10→20, `trading.position-rate` 10→5 (dev/prod + 두 클래스 @Value 전부 정합).

### Dashboard (`system-trading.html`, `system-overview.html`, `system-monitoring.html`)
- 사이징 서사·리스크표·요약을 신규 정책(20종목·종목당 총자산 5%·미배분 현금 보유)으로 정합. 하드코딩 "10종목/10%" 잔재 제거.
- ⚠️ 표시값은 여전히 **정적 하드코딩** — 설정 변경 시 함께 수정 필요.

## 새 동작 (사용자 관점)
- 각 매수는 총자산의 5%로 고정. 첫날 신호 2개면 5%+5%=10%만 쓰고 90%는 현금 보유.
- 이후 사이클/날마다 새 신호가 뜰 때마다 5%씩 추가 매수 → 최대 20종목까지 점진적으로 균등 분산.
- 책이 채워져 현금이 줄어도 상한이 총자산 기준이라 종목별 비중이 ~5%로 균등 유지.

## 다음 단계 참조
- **[미해결·핵심] 신호 희소성**: 이번엔 사이징만 고쳤다. 첫날 신호가 2개뿐이었던 건 별개 문제로, `min-score=120`이 엄격해 후보가 적다. 분산이 실제로 20종목까지 채워지려면 신호가 충분히 생성돼야 한다. min-score 완화/데이터 결핍(DART 재무·주가 이력)은 중대 등급 전략 변경이라 **사용자와 별도 논의 필요**. (아키텍처맵 §3~4, stall-diagnosis 참조)
- **[개선]** 대시보드 사이징 표시값이 정적 하드코딩 → 설정값을 서버에서 `th:text`로 내려 표시하는 동적 바인딩으로 전환하면 향후 설정 변경 시 자동 반영. 소규모 후속 과제.
- **[관측]** 배포 후 첫 매매일에 실제로 종목당 ~5% 배분·잔여 현금 보유가 관측되는지 대시보드/로그로 확인 권장.
- **[결정 이유]** 총자산 기준(가용현금 기준 아님)을 택한 이유: 가용현금 기준이면 매수할수록 현금이 줄어 후속 종목 비중이 기하급수적으로 작아져(기하급수 축소) 비중 불균등 발생. 총자산 기준은 책이 채워져도 각 종목 ~5% 균등 유지.
