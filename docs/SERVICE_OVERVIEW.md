# CAN Agent 서비스 개요

> 자동화 주식 매매 시스템 - CANSLIM + Cup&Handle 전략 기반 실시간 모니터링 및 자동 매수

---

│ Worker   │ Worker   │              │                         │

│                    분석 엔진                                   │
│  ┌─────────────────┐  ┌──────────────────────┐               │

│  │ Service         │  │                      │               │
│  └─────────────────┘  └──────────────────────┘               │
├──────────────────────────────────────────────────────────────┤

## 2. 스케줄 전체 도표

| 시간 (KST) | Worker | 작업 내용 | 소요시간 |
|---|---|---|---|
| **09:00** | IntradayMonitorWorker | 장중 모니터링 #1 (거래량/변동률 상위 ~400종목 스캔) | ~2~3분 |
| **09:00** | AutoTradingWorker | 일일 자동매매 (전체 2,763종목, 어제 종가 기준) | ~40~60분 |
| **09:05~15:30** | IntradayMonitorWorker | 장중 모니터링 (5분 간격) | ~2~3분/회 |
| **15:30** | DataSyncScheduler | 일일 주가 데이터 동기화 (KRX) | ~5~10분 |
| **분기별 1/4/7/10월 10:00** | DataSyncScheduler | 분기 재무제표 동기화 (DART) | ~30분 |

> **주의**: 현재 AutoTradingWorker와 IntradayMonitorWorker가 동일 스레드에서 실행되어, AutoTradingWorker가 끝나기 전까지 IntradayMonitorWorker의 후속 실행이 대기됩니다. (스케줄러 멀티스레드 설정 필요)

## 3. IntradayMonitorWorker - 핵심 모니터링 사이클

### 3.1 실행 흐름

```
크론 트리거 (5분 간격, KST 9:00~15:30)
  │
  ├─ 장중 여부 확인 (isTradingHours) ── 장중 아님 → 종료
  │
  ├─ 대상 종목 선정 (getTargetStocks)
  │   ├─ 어제 거래량 상위 200개 (stock_prices 테이블)
  │   ├─ 어제 가격 변동률 상위 200개 (stock_prices 테이블)
  │   └─ 중복 제거 → 약 300~400개
  │
  ├─ 각 종목별 현재가 조회 + 분석 (500ms 간격)
  │   ├─ 한국투자증권 현재가 API 호출
  │   ├─ 기 보유 종목이면 스킵
  │   ├─ CANSLIM 분석 실행
  │   ├─ Cup & Handle 분석 실행
  │   └─ 매수 신호 판정
  │
  ├─ 매수 신호 발생 시 ── 장중 재확인 후 매수 실행
  │   ├─ 최대 보유 종목 수 확인 (기본 10개)
  │   ├─ 예수금 조회
  │   ├─ 점수 비례 포지션 사이징
  │   ├─ 주문 실행 (1초 간격, 실패 시 3회 재시도)
  │   └─ 알림 발송
  │
  └─ 결과 저장 (대시보드 표시용)
```

### 3.2 매수 신호 포착 조건

| 조건 | 기준 | 설명 |
|---|---|---|
| **CANSLIM 매수** | `totalScore >= 40` | 6개 항목 합산 (최대 90점) |
| **컵앤핸들 매수** | `breakout = true` | 가격이 컵 패턴 고점 돌파 |
| **최소 점수** | `CANSLIM + 컵앤핸들 >= 120` | 합산 점수 (최대 180점) |
| **보유 중 아니어야 함** | `portfolio.active = false` | 이미 보유한 종목은 스킵 |

### 3.3 포지션 사이징 (점수 비례 배분)

```
종목별 투자금 = 총 예수금 × (해당 종목 점수 / 매수 대상 총점)

예시:
  예수금: 100,000원
  매수 대상: A종목(130점), B종목(110점) → 총점 240점
  A종목 배분: 100,000 × (130/240) = 54,166원 → 54,166 / 현재가 = 수량
  B종목 배분: 100,000 × (110/240) = 45,833원 → 45,833 / 현재가 = 수량
```

- 최소 주문금액: 5,000원 미만이면 주문 스킵
- 수량은 내림 (소수점 이하 버림)
- 주문 간 1초 딜레이

## 4. CANSLIM 분석 점수 체계

**최대 90점**, 6개 항목으로 구성:

| 항목 | 최대점수 | 배점 기준 |
|---|---|---|
| **분기별 EPS 성장률** | 20 | >=25% → 20, >=10% → 16, >=5% → 12, >0% → 8 |
| **연간 EPS 성장률** | 20 | >=25% → 20, >=10% → 16, >=5% → 12, >0% → 8 |
| **수급 (거래량 비율)** | 15 | 거래량비>=2.0+가격상승 → 15, >=1.5 → 12, >=1.2 → 9 |
| **시장 방향성** | 15 | 현재가>MA50 +5, MA50>MA200 +5, 골든크로스 +5 |
| **업종 리더** | 15 | 업종상위10%+ROE>=20% → 15, 상위25% → 12, 상위50% → 9 |
| **기관 투자자** | 15 | 매집(거래량신고가+가격상승) → 15, 보통매집 → 9 |

**매수 기준**: `totalScore >= 40` (강력매수: `>= 60`)

## 5. Cup & Handle 분석 점수 체계

**최대 90점**, 패턴 인식 기반:

| 단계 | 조건 | 점수 |
|---|---|---|
| **컵 형성** | 기본 점수 | +30 |
| **컵 깊이** | 20~25% (최적) | +10 |
| **컵 기간** | 7~30주 (최적) | +10 |
| **핸들 깊이** | 10~12% (최적) | +20 |
| **핸들 깊이** | 그 외 | +10 |
| **돌파 (Breakout)** | 현재가 > 핸들 고점 | +20 |

**매수 기준**: `breakout = true` (실제 가격 돌파 시에만 매수)

## 6. 매도 조건

| 조건 | 기준 | 설명 |
|---|---|---|
| **손절** | 수익률 <= -7% | 평균 매수가 대비 -7% 이하 |
| **익절** | 수익률 >= +20% | 평균 매수가 대비 +20% 이상 |
| **CANSLIM 점수 하락** | totalScore < 40 | 보유 종목의 CANSLIM 점수가 40 미만으로 하락 |

## 7. AutoTradingWorker (일일 자동매매)

> **레거시 워커**: 매일 장 시작(09:00)에 전체 종목을 한 번에 스캔

| 항목 | 내용 |
|---|---|
| **크론** | `0 0 9 * * MON-FRI` (매일 오전 9시) |
| **대상** | 전체 활성 종목 (2,763개) |
| **가격 기준** | 어제 종가 (DB에서 조회, 실시간 아님) |
| **분석** | CANSLIM + Cup & Handle |
| **매수 기준** | min-score 120 |
| **매도 기준** | 손절(-7%), 익절(+20%), CANSLIM 점수 하락(<40) |
| **소요시간** | 약 40~60분 (전체 종목 순회) |

> AutoTradingWorker는 IntradayMonitorWorker와 동시에 실행되지만, Spring 기본 스케줄러가 단일 스레드이므로 상호 대기 상태가 됨.

## 8. 데이터 동기화 스케줄

### 8.1 일일 주가 데이터 (DataSyncScheduler)
- **크론**: `0 30 15 * * MON-FRI` (매일 오후 3시 30분)
- **내용**: KRX에서 전체 활성 종목의 전일~금일 주가 데이터 수집
- **테이블**: `stock_prices` (stock_id, date, open, high, low, close, volume, change_rate)

### 8.2 분기 재무제표 (DART)
- **크론**: `0 0 10 1,4,7,10 *` (1/4/7/10월 10시)
- **내용**: DART에서 분기별 재무제표 수집
- **테이블**: `financial_statements` (매출, 영업이익, 당기순이익, EPS 등)

## 9. 포지션 관리

| 설정 | 기본값 | 설명 |
|---|---|---|
| `max-positions` | 10 | 최대 보유 종목 수 |
| `position-rate` | 10% | 종목당 최대 배분 비율 |
| `stop-loss-rate` | 7% | 손절 기준 수익률 |
| `take-profit-rate` | 20% | 익절 기준 수익률 |
| `min-score` | 120 | 매수 최소 점수 (합산) |

## 10. 매수 실행 상세

```
1. 매수 신호 종목을 점수순으로 내림차순 정렬
2. 최대 보유 가능 수 = max-positions - 현재 보유 종목 수
3. 상위 N개만 매수 대상 (가장 점수가 높은 종목 우선)
4. 각 종목별 투자금 = 예수금 × (종목점수 / 매수대상총점)
5. 수량 = 투자금 / 현재가 (내림)
6. 5,000원 미만이면 스킵
7. 한국투자증권 매수 API 호출
   - 성공 → Portfolio 저장 + Trade 저장 + 알림 발송
   - 실패 → 1초 대기 후 재시도 (최대 3회)
8. 다음 종목으로 1초 대기 후 이동
```

## 14.Known Issues

1. **스케줄러 멀티스레드 미설정**: AutoTradingWorker(40~60분) 실행 중에는 IntradayMonitorWorker가 대기됨. `ThreadPoolTaskScheduler` 설정 필요.
2. **API Rate Limiting**: 한국투자증권 API 초당 호출 제한 존재. 현재 500ms 간격으로 대응 중.
3. **장 마감 후 매수 방지**: 스캔 완료 후 매수 실행 전 `isTradingHours()` 재확인으로 대응.
